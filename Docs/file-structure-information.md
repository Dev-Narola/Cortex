Here's the purpose of every folder and file, organized top to bottom.

## Root level

| Path | Purpose |
|---|---|
| `src/cortex/` | All application source code lives here (the "src layout" — keeps package code separate from config/tests at root) |
| `alembic/` | Database migration history — every schema change gets one versioned file here, generated by Alembic and reviewed by hand |
| `tests/` | All automated tests, mirroring the source structure |
| `docs/adr/` | Architecture Decision Records — short write-ups justifying non-obvious choices ("why pgvector," "why modular monolith") |
| `scripts/` | One-off operational scripts you run manually (seeding dev data, forcing a tenant reindex) — not part of the running app |
| `docker/` | Container definitions for local dev and deployment |
| `.github/workflows/` | CI/CD pipeline definitions (test-on-push, deploy-on-merge) |
| `.env.example` | Template listing required environment variables, with no real secrets — copied to `.env` locally |
| `pyproject.toml` | Python project metadata + dependencies (replaces requirements.txt) |
| `alembic.ini` | Alembic's config file (tells it where migrations live, how to reach the DB) |
| `README.md` | Setup instructions and project overview |

## `main.py`
The entrypoint. Creates the FastAPI app instance and wires every context's router into it (REST routers, the GraphQL endpoint, the WebSocket handler, the MCP server). Nothing else — no business logic here.

---

## `identity/` — tenants, users, auth, RBAC, API keys
Handles "who is making this request, and what are they allowed to do."
- **`domain/entities.py`** — plain Python classes for `Tenant`, `User`, `ApiKey`, `Role`. No database or web framework knowledge — just the rules (e.g. "a role must be one of owner/admin/member/viewer").
- **`application/services.py`** — use cases like `RegisterTenantService`, `AuthenticateUserService` — orchestrates domain rules + infrastructure calls.
- **`infrastructure/models.py`** — SQLAlchemy table definitions (the ORM's view of `tenants`, `users`, `api_keys`).
- **`infrastructure/repositories.py`** — the actual DB queries (save user, find tenant by id) — the only place SQL/ORM calls happen.
- **`infrastructure/security.py`** — JWT signing/verification, password hashing, API key hashing.
- **`interface/rest/routes.py`** — the HTTP endpoints (`/auth/register`, `/auth/login`, `/api-keys`) that call the application services.

## `ingestion/` — upload → parse → chunk → embed
Turns a raw uploaded file into searchable chunks.
- **`domain/entities.py`** — `Document`, `Chunk` — what a document/chunk *is*, independent of how it's stored.
- **`application/services.py`** — `IngestDocumentService`, coordinating the whole parse→chunk→embed flow.
- **`application/chunking.py`** — the actual chunking strategy/logic (splitting text sensibly).
- **`infrastructure/models.py`** — ORM tables for `documents`, `document_chunks`.
- **`infrastructure/storage.py`** — talks to S3 to store/retrieve raw files.
- **`infrastructure/parsers.py`** — extracts text from PDFs, Word docs, HTML, etc.
- **`infrastructure/embedding_client.py`** — calls the embedding model API to turn text into vectors.
- **`interface/rest/routes.py`** — `/documents` endpoints (upload, list, status).
- **`workers/tasks.py`** — the background jobs (Celery/Arq) that actually run ingestion off the request path, with retry logic.

## `retrieval/` — hybrid search, reranking, knowledge graph
Answers "given a query, what's relevant."
- **`domain/entities.py`** — `KGEntity`, `KGRelation` — the building blocks of the knowledge graph.
- **`application/hybrid_search.py`** — combines keyword (BM25) and vector search results.
- **`application/reranker.py`** — re-scores/reorders search results for better relevance.
- **`application/kg_extraction.py`** — logic for pulling entities/relationships out of chunk text using an LLM.
- **`infrastructure/vector_repository.py`** — pgvector queries.
- **`infrastructure/graph_repository.py`** — queries against the `kg_entities`/`kg_relations` tables.
- **`interface/rest/routes.py`** — `/search`, `/kg/entities` endpoints.
- **`interface/graphql/schema.py`** — the GraphQL schema for graph-shaped traversal queries.

## `conversation/` — chat sessions, streaming, context
Manages the actual back-and-forth chat experience.
- **`domain/entities.py`** — `Conversation`, `Message`.
- **`application/services.py`** — `AnswerQueryService` — ties retrieval + LLM generation together into an answer.
- **`application/context_manager.py`** — decides what context/history fits into the LLM's context window.
- **`infrastructure/repositories.py`** — saves/loads conversations and messages from Postgres.
- **`interface/rest/routes.py`** — `/conversations` CRUD endpoints.
- **`interface/websocket/handlers.py`** — the `/ws/conversations/{id}` handler that streams tokens back live.

## `agents/` — tool calling, agent loop, MCP
Lets the system take multi-step actions, and exposes those actions to outside AI agents.
- **`domain/entities.py`** — `AgentRun`, `ToolCall` — what an agent run and its individual tool invocations look like.
- **`application/agent_loop.py`** — the actual reasoning loop (think → call tool → observe → repeat, with safeguards against infinite loops).
- **`application/tool_registry.py`** — the list of tools an agent is allowed to call and how to invoke them.
- **`infrastructure/repositories.py`** — persists agent runs and tool call logs.
- **`interface/rest/routes.py`** — `/agents/runs` endpoints for triggering/checking agent runs.
- **`interface/mcp/server.py`** — the MCP server itself, including tenant-scoped OAuth so external agents only see their own tenant's data.
- **`interface/mcp/tools.py`** — the actual MCP tool definitions (`search_knowledge_base`, `ask_knowledge_base`, etc.) exposed to outside clients like Claude.

## `billing/` — usage metering, rate limiting
Tracks cost and enforces limits per tenant.
- **`domain/entities.py`** — `UsageEvent` — one billable/loggable action.
- **`application/rate_limiter.py`** — logic deciding whether a request is within a tenant's allowed rate.
- **`infrastructure/redis_counters.py`** — the actual token-bucket counters stored in Redis.
- **`interface/rest/routes.py`** — `/tenants/me/usage` for tenants to see their own consumption.

## `observability/` — tracing, metrics, audit log
The system watching itself.
- **`tracing.py`** — OpenTelemetry setup so every request/LLM call is traced end-to-end.
- **`metrics.py`** — counters/gauges (latency, error rates, etc.).
- **`audit_log.py`** — writes append-only records of who did what, for compliance.
- **`interface/rest/routes.py`** — `/health`, `/metrics` endpoints used by monitoring tools and load balancers.

## `platform/` — shared infrastructure, no business logic
The plumbing every other context relies on but that isn't itself a "feature."
- **`config.py`** — reads environment variables/settings into a typed config object.
- **`secrets.py`** — pulls secrets (API keys, DB passwords) from wherever they're stored (env, AWS Secrets Manager).
- **`database.py`** — sets up the SQLAlchemy engine and session factory that every context's repositories use.
- **`redis_client.py`** — the shared Redis connection.
- **`llm_provider.py`** — the adapter that actually calls OpenAI/Anthropic — one place to swap providers or add retry/cost logic.
- **`dependencies.py`** — shared FastAPI dependency functions, e.g. `get_current_tenant`, injected into route handlers across contexts.

## `shared/` — the tiny common kernel
Only things so generic that *every* context might reasonably need them.
- **`exceptions.py`** — common exception types (e.g. `NotFoundError`, `PermissionDeniedError`) so error handling is consistent across contexts.
- **`pagination.py`** — reusable pagination helpers for list endpoints.

---

## `tests/`
- **`unit/`** — fast tests with no real DB/network, mirroring the `src/cortex/` folder structure one-to-one, so `identity/application/services.py` has a matching `unit/identity/application/test_services.py`.
- **`integration/`** — slower tests that spin up real dependencies (test DB, etc.) and check full flows work end to end, e.g. `test_ingestion_pipeline.py` uploads a real file and checks it ends up indexed.
- **`conftest.py`** — shared pytest fixtures (test DB session, test client, fake tenant) available to all tests.

---

**One structural note worth flagging:** a few contexts (`observability`, `platform`, `shared`) don't have the full `domain/application/infrastructure/interface` split — that's intentional, not inconsistent. Those folders hold cross-cutting technical concerns rather than business use cases, so forcing them into the same four-layer shape would just be ceremony without benefit.
