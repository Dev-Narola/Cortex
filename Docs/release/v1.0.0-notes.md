# Cortex v1.0.0 — Release Notes

V9 Part 4, Task 50.

## Summary

Cortex v1.0.0 is the first **enterprise-grade** release of
the platform. It is the first release that comes with a
documented production-readiness review, a CI quality gate,
disaster-recovery validation, and an operations runbook set
that a new engineer can follow end-to-end.

## Known limitations

1. **Knowledge graph backend** — currently Postgres
   (per ADR-0004); Neo4j is forward-compat but not
   enabled. The seam (`GraphDatabaseClient`) is in place.
2. **Benchmark baselines** — the first release's
   baselines are placeholders. The real baselines will
   be recorded after the first 7 days of production
   traffic.
3. **Multi-region active/active** — only active/passive
   is supported today. Active/active requires the
   read-model projection to become multi-master.
4. **AWS Secrets Manager backend** — the
   `SecretProvider` is a forward-compat seam; only
   env / docker / in-memory backends are wired.
5. **Vault backend** — not implemented; the
   `SecretProvider` interface is the integration point.

## Upgrade guide

If you are upgrading from a pre-v1.0.0 release:

1. Read the migration notes in
   `alembic/versions/v9_*`.
2. Run `alembic upgrade head`.
3. Restart the API and workers.
4. Run the smoke test suite.

The breaking changes are:

* `app.cortex.config.Settings` now requires the V9 keys;
  missing keys default to safe values.
* The `Platform.dependencies` module reorganised; the
  old import paths still work via the backward-compat
  shims under `src/retrieval/application/search_service.py`.
